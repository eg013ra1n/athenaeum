# Logging Overhaul — Design

**Date:** 2026-07-03 · **Status:** approved-pending-review · **Owner decisions baked in:** scope = backend + submodules (frontend console out of scope); level control = Settings UI + env override; approach = `tracing` backbone + structured JSONL files + MCP query server (cut-able last phase).

## Problem

Athenaeum has no real logging. The de-facto mechanism is ~516 `println!`/`eprintln!` sites across the backend (scanner and fits_parser densest), which vanish in a normal desktop launch; the hand-rolled `logging.rs` (single 5 MB file, no levels, no filtering) is called from almost nowhere; the submodules (solvemyastro, rustafits) print to stdout; the frontend logs to a DevTools console nobody has open. Debugging a user report means asking them to relaunch from a terminal. There is no tiering (info/warn/error/debug), no per-module verbosity, no machine-readable format, and no way to pull "everything that happened during solve X".

## Goals

1. Every command and every math-heavy operation logs through one leveled, structured API.
2. Four user-facing tiers — `error` / `warn` / `info` / `debug` — plus `trace` for per-item math detail (env-only).
3. **Unified event style**: same envelope everywhere; per-domain required fields from a canonical catalog; data in fields, never interpolated into message prose.
4. Runtime level control: Settings UI (global + per-module, live, no restart) with `ATHENAEUM_LOG` env override; works in both backends.
5. Logs stored as rotating JSONL files — the single source of truth for dev sessions, Docker, and beta-user support bundles alike.
6. A small MCP server for dev-time querying of those files (filter by level/module/time/operation).
7. Logging can never take the app down or measurably slow disabled-level hot paths.

## Non-goals (explicit)

- Frontend console forwarding into the backend log (own design questions — later cycle).
- Log shipping / telemetry of any kind (nothing leaves the machine).
- Replacing `ProgressEmitter` (progress is UI data, not logs) or the notification system.
- An in-app log-viewer UI.
- Changing `CellTrace`/diag structures in solvemyastro (solve-result data, not logging) — only its stdout prints migrate.

## Architecture

`tracing` is the sole logging API in all five Rust codebases:

- **core / tauri / web**: full `tracing` usage; subscriber initialization lives in a rewritten `athenaeum_core::logging` and is invoked from both hosts' `main`.
- **solvemyastro / rustafits**: the lightweight `tracing` facade only (macros + spans, no subscriber). Standalone binaries/benches in those repos may init a simple fmt subscriber behind their own `main`s; as workspace path-deps their events flow into the host subscriber automatically.

Subscriber stack (both hosts, one code path in core):

1. **JSONL file layer** — one JSON event per line, non-blocking writer (`tracing-appender` dedicated thread), daily rotation with max-files cap (default: 14 files). Location: `<app-data>/logs/` (desktop), `/data/logs/` (Docker).
2. **Console layer** — pretty human format; always on for the web server (Docker convention: JSON to stdout as well), dev-visible for desktop terminal launches.
3. **Reloadable filter** — `EnvFilter` behind a `reload::Layer` handle. Filter directives come from settings (below) or `ATHENAEUM_LOG` when set.

The existing panic hook + `crash.log` behavior is preserved (panic also emitted as an `error` event). The old single-file `athenaeum.log` writer is deleted. `get_log_path` returns the live log directory/current file. Uninstall scripts gain the `logs/` location (house rule).

Multi-process safety: desktop and web pointed at the same app-data dir use per-process file prefixes (`athenaeum-desktop.*`, `athenaeum-web.*`) so rotation never races.

## Levels

| Level | Meaning | Examples |
| ---- | ---- | ---- |
| `error` | Operation failed; user-visible consequence. Always logged; the command boundary guarantees no swallowed Err. | command returned Err; file op failed; restore conflict |
| `warn` | Recoverable / suspicious; a fallback or assumption was taken. | NULL binning treated as 1×1; poisoned lock recovered; retry taken; filter parse error kept previous filter |
| `info` | Operation lifecycle. The level a beta user runs at. | command invoked/completed + duration; scan finished with counts; solve outcome + confidence |
| `debug` | Stage-level internals. | per-file scanner decision; per-set calibration score; solver stage timings |
| `trace` | Per-item math detail. Env-only (not in the Settings UI), off by default, negligible disabled cost. | per-star, per-quad, per-inlier iteration |

## Unified event schema

**Base envelope** (every event; mostly free from the JSONL layer): `timestamp`, `level`, `target` (module path), `message`, span context (operation kind + id + host span fields).

**Canonical field dictionary** — never ad-hoc synonyms. Core names: `frame_id`, `file_id`, `frame_set_id`, `set_id` (calibration set), `root_id`, `operation_id`, `command`, `path`, `src`, `dest`, `duration_ms`, `count`, `error`, `outcome`, `stage`. snake_case only. New fields extend the dictionary in this spec via PR — not invented inline.

**Dictionary extensions (added during implementation, T1):** scan-summary counts `found`, `processed`, `skipped`, `modified` (siblings of the scan-domain counts `seen`/`new`/`updated`/`errors` and the example's `unchanged`; the Task 5 scanner sweep table reconciles final scan-count naming); `monitor_enabled` (bool, scan-root monitor toggle); `addr` (server bind address); `directives` (EnvFilter directive string on logging-filter events); `frame` (string; source frame filename in solver-submodule contexts, which have no DB row id — deliberately distinct from core's numeric `frame_id` so MCP queries never mix the two); T8.

**Dictionary extensions (sync connection-path diagnostics, `sharing::iroh`):** `peer` (short hex id of the remote endpoint on a connection-path event); `direction` (`"outgoing"`/`"incoming"` — which side established the QUIC connection); `conn_type` (`"direct"`/`"relay"`/`"mixed"`/`"pending"` — a connection's transport-path classification, or `"direct"`/`"relay"`/`"other"` on a path-change event); `relay_url` (the home relay URL an endpoint connected to); `relay_mode` (`"disabled"`/`"default"`/`"staging"`/`"custom"` — what the endpoint was actually built with); `relay_count` (number of relays in the endpoint's relay map); `timeout_ms` (a configured wait bound, e.g. the home-relay `online()` timeout — distinct from `duration_ms`, which is elapsed time); `role` (`"recv"`/`"out"`/`"collab"` — the `SharedIrohNode` role whose blob-tag prefix a startup sweep scoped to, per the 2026-07-15 iroh hardening); `kind` (`"announce"`/`"ack"`/`"project_announce"`/`"project_request"`/`"fetch_progress"` — the inbound transport-event variant an orphan-drop warn names when the `SharedIrohNode` event demux finds no `(peer, package)` claim or Recv consumer, per the 2026-07-15 iroh hardening; on this event `peer` also carries the source endpoint's hex id). Reuses `addr` for a connection's selected remote transport address (its `ip:<socket>` / `relay:<url>` Display), extending the T1 "server bind address" sense to any transport address.

**Dictionary extensions (sync retry backoff, `sync::engine`, TEST-11 2026-07-16):** `delay_ms` (u64; the backoff window a package will now wait before its next re-announce — the just-computed `retry_backoff(ack_timeout, rung)` in ms, distinct from `duration_ms`/`timeout_ms`: it is a scheduled future wait, not elapsed time or a configured bound); `next_retry_at` (RFC3339-UTC-millis wall-clock instant the retry is scheduled for — the same stamp persisted to `OutboundRow::next_retry_at`, reused for the log so a one-line `query_logs` on the `"ack timeout, backing off"` event answers "when does it retry" without watching the UI countdown). `forced` (bool) rides the `sharing::iroh` `"relay map node rebuild complete"` event (TEST-12) alongside the existing `relay_count`: whether the deferred rebuild fired past the idle gate (max-defer) or on a quiet instant.

**Dictionary extension (FITS writer sanitize, `fits_writer::card`, 2026-07-18):** `keyword` (the FITS header keyword whose string value/comment/text contained non-printable-ASCII chars and was lossily degraded to `?` placeholders on the `"non-ASCII characters in header value sanitized"` warn — the ATH_REJ master-build bug-report fix).

**Dictionary extension (send+receive concurrency instrumentation, `sync` + `sharing::iroh`, Problem 4 Task 4.1 2026-07-19):** `op` (a stable snake_case name for the store write being timed on the `"sync store write slow"` warn — `"receiver_ingest"` for the receiver's per-frame ingest transaction, `"confirm"` for the sender's ack-confirm write). Reuses `duration_ms` (elapsed time) on that warn, on the `"sync receiver announce handled"` info (inline announce-handling time, candidate (a)), and on the `"inbound event delivery delayed"` warn (the `tx.send().await` wait to hand a decoded inbound event to its consumer — candidate (a): a blocked send means the receiver loop was busy). Reuses `kind` (the inbound transport-event variant — same values as the orphan-drop warn) and `peer` on that delivery-delayed warn, and reuses `from` (short hex id of the announcing peer) + `package_id` on the announce-handled info. All three are behavior-neutral timing events for discriminating the smoke-reported "can't receive while sending".

**Dictionary extension (sync send-path dial classification, `sync::engine`/`sync::diagnostics`, 2026-07-19):** `class` (stable snake_case dial-outcome class of a failed serve/announce attempt — `no_route`/`relay_unreachable`/`refused`/`timeout`/`not_started`/`other` — derived string-only from the `anyhow`-chain error text on the `"sync serve/announce failed; will retry"` event, and mirrored as the machine-readable prefix of the outbound row's `last_error`; a best-effort diagnostic hint, never an authorization signal).

**Dictionary extension (transport telemetry, `sharing::iroh::telemetry`, 2026-07-25):** `window` (`"tick"`/`"session"` — what span of time the `"transport traffic"` counters cover: one sampler interval, or the whole run from bind to shutdown); `send_relay_bytes` / `send_direct_bytes` / `recv_relay_bytes` / `recv_direct_bytes` (u64 bytes moved over a relay vs a direct IP path in that window — the split that answers "is hole punching actually working / what is the relay costing us", unanswerable before, because the bulk of a transfer runs inside iroh-blobs' own connection pool); `paths_direct` / `paths_relay` (network paths of each kind opened); `holepunch_attempts` (hole punches initiated, client side only); `relay_home_change` (home-relay changes incl. the initial assignment — a steadily climbing value is relay ping-pong, not healthy re-homing); `conns_direct` / `conns_opened` (connections that ended up direct, of those opened). `conn_path` (`"direct"`/`"relay"`/`"mixed"`/`"other"`/`"unknown"`) rides the per-package `"iroh fetch complete"` info: how the peer was reachable when the payload finished, from the endpoint's own remote map — deliberately distinct from `conn_type`, which classifies ONE instrumented control connection, where this classifies every active path to a peer.

**Dictionary extension (calibration supersede-hardening, `calibration::superseded_guard` + `calibration_library::light_cal` + `api::lights`, 2026-08-02):** `covered` / `uncovered` (usize; on the superseded-guard's `"group PARTIALLY superseded — uncovered frames get no set this pass"` warn — how many of the group's frames the winning master's raw set actually held, and the remainder that therefore get no set this pass; they sum to the event's `count`); `floored_flat_pixels` (u64; pixels whose flat denominator hit `FLAT_DENOM_FLOOR` because the flat pixel was dead/negative/non-finite — carried by the engine's `"flat denominator floored (dead/negative flat pixels)"` warn as `count` and re-reported per frame on the `"light calibration recorded"` debug under its own name, since that event already spends `count` elsewhere); `total` (u64; the frame's pixel count on that same flat-floor warn, so the floored count reads as a fraction — a few hundred hits mean something different on a 1 MP frame than on a 60 MP one); `scale_divisor` (f64; the BITPIX-derived output scale a light frame was actually divided by — `scale_divisor_for_bitpix`, also stamped as the output's `ATH_CSCL` card — logged per frame so a mis-scaled artifact is diagnosable from the log alone, without re-reading the FITS header).

**Dictionary extension (calibrated export v2, `export::{file_organizer, calibrated_generator}` + `calibration_library::{cosmetic, light_resolve}` + `api::{lights, sync_prepare}`, 2026-08-31):** `resolved` (usize; on the `"calibrated-light generation planned"` info — lights whose calibration inputs resolved, i.e. how many the batch will generate) and `skipped` (usize; same event — lights that could NOT be resolved and will be skipped, each already logged its own reason on the `"cannot calibrate this light — it will be skipped"` warn; a second, consistent use of the name that already carries the T1 scan-summary sense, not a synonym); `flat_divisors` (usize; same event, plus the send-side `"calibrated-light generation planned for a transfer"` info — distinct flat-normalization divisors the batch resolved, one per master flat, the cache-size signal for the plan); `named_debayer` / `resolved_debayer` (bool; on the `"debayer decision disagrees with the placed filename"` warn, logged together only when they differ — what the `_d` filename suffix claimed vs what the generator actually resolved, a bug signal); `debayered` (bool; whether the written artifact was VNG-debayered) and `hot_pixels_replaced` (u64; pixels the cosmetic pass replaced in this frame, `0` when the map was refused or the option is off), on both the export's `"calibrated light written into the export"` debug and the send's `"calibrated light staged into a package"` debug; `calstat` (string; the `CALSTAT` value actually stamped on the output — `BDF`/`BD`/`BF`/`B`/`F` — on those same two debugs plus the generator's own `"light calibrated"` debug); `flat_norm_divisor` (f64; the divisor the flat was normalized by, `1.0` = normalization off) and `cfa_scaling_applied` (bool; whether it was applied per CFA channel rather than as one global scalar), on that `"light calibrated"` debug, alongside `width` / `height` (usize; the frame's pixel dimensions), reused on the hot-pixel-map build debug; `median` / `mad` / `threshold` (f32; on the `"hot-pixel map built"` debug — the master dark's median, its median absolute deviation, and the derived detection threshold; a zero MAD is what makes the map refuse); `field` (string; on the `"cfa phase not declared — per-channel flat scaling assumes 0"` debug — which header field(s) were absent, `"xbayroff"` / `"ybayroff"` / `"xbayroff,ybayroff"`); `note` (string; on the send path's `"calibrated light staged with a warning"` warn — a non-fatal per-frame note, today only a refused hot-pixel map; the send has no per-file warning channel, so this is `warn!`-only, where export folds the identical text into `OrganizeResult::warnings` instead); `missing_master_files` (i64; on the `"export readiness computed"` debug — distinct resolved master FILES that no longer exist on disk, the C-2 readiness blocker) and `raw_sets` (usize; same event — raw calibration sets with no master yet).

**Dictionary extension (master-build lifecycle logging, `api::masters`, integration-throughput cycle Task 7, 2026-09-06):** `imagetyp` (string; the calibration set's frame type, LOWERCASED (`"dark"`/`"flat"`/`"bias"`/`"darkflat"`) on the `"master build started"` info — the calibration_set row's own value is title-case, but the pre-existing informal emitters in `calibration::scan_integration` already lowercase it for their own debugs; fix round 2 (minor) matched that convention rather than formalizing a second casing, so one filter finds both); `recipe` (string; the resolved `IntegrationRecipe::describe()`, e.g. "Average \| Winsorized sigma (3.0/3.0)", on that same info); `budget_mb` (u64; `io.band_budget_bytes` converted to MB, the band-size ceiling the run resolved to); `read_threads` (usize; `io.read_concurrency` — NOT a CPU-derived number (spec §7, D3 retired that policy): it comes from `StorageClass` instead, MORE than core count on a network mount — logged alongside `storage` so a pending SSD/NAS measurement can be read against the policy that actually produced it); `storage` (string; `StorageClass::as_str()` — `"local"`/`"network"` — the storage class `io_policy::resolve` classified the set's paths as, logged alongside `budget_mb`/`read_threads` on that same info for the same reason). Reuses `duration_ms` (elapsed wall time from budget resolution to the engine returning — NOT the whole build; write + register happen after this line) on the `"master build finished"` info, alongside `read_ms`/`combine_ms` (u64; `IntegrationOutput::read_duration`/`combine_duration` in ms — the engine's own phase split, since only it can tell the two bottlenecks apart), `read_mb_s` (u64; `bytes_read` divided by `read_duration`'s seconds, divided by 1e6, rounded — true megabytes/second, not bytes/second — `0` when the duration is `0`), and `band_rows`/`bands` (usize; the two numbers the band budget actually decided — for a FLAT these describe pass 2 only, see the `IntegrationOutput` field docs and `EngineProgress::on_band`'s doc for why that disagrees with `bytes_read`/`read_duration`, which span both passes).

**Dictionary extension (stacking measurement, `stacking::measure`, 2026-09-09):** `plane` (usize; the 0-based plane index of a multi-plane calibrated frame on the `"frame plane measured"` debug), `stars_detected` / `stars_fitted` (usize; detections handed to the PSF fitter and fits accepted, same event), `beta` (f64; the Moffat β the plane was fitted with), `fwhm_px` / `eccentricity` (f64; the residual-weighted frame FWHM in pixels and eccentricity), `noise` (f64; the plane's noise σ in native [0, 1] units — MRS, or the background-residual scale when MRS was unavailable, which the `"MRS noise unavailable; using the background residual scale"` warn announces with `n_star` (f64; that scale, in the estimator's ADU-scaled units)), `psf_signal_weight` / `psf_snr` (f64; the two PSF-signal estimators, math reference §1.2). Reuses `path` and `duration_ms` (the plane's measurement time) on that debug.

**Dictionary extension (stacking measurement, M4a Task 2, `stacking::measure`, 2026-09-11):** `detection_sigma` (f32; the noise-relative star-detection threshold the plane's seed population was found at — the detector's two ladder levels are `background + detection_sigma·noise` and `background + (detection_sigma/2)·noise`, spec §9.2 `measurement.detectionSigma`) on the `"frame plane measured"` debug, alongside the `stars_detected` it explains, plus `seed_prefilter` (string; the image that detection ran on — `"none"` or `"median3"`, `SeedPrefilter::as_str`, i.e. the same spelling the stored config uses — added in the same task's fix round 1, ruling R-M4a-13: everything downstream of detection always measures the untouched plane, so this field is the only record of which image the seeds came from).

**Dictionary extension (stacking measurement, M4c Task 0, `stacking::measure` + `stacking::structure`, 2026-09-11):** `seed_detector` (string; WHICH detector produced the plane's seeds — `"peak"` or `"structure"`, `SeedDetector::as_str`, the same spelling the stored config uses, spec §9.2 `measurement.seedDetector`) on the `"frame plane measured"` debug, beside the `detection_sigma`/`seed_prefilter` that only the peak detector reads. The structure detector adds its own `"structure map seeds detected"` debug with `structures` (count of connected structures the map produced, before any per-candidate rule), `threshold` (f32; the binarization level in the plane's own units) and `min_star_size` (the size floor the automatic mode derived from the population, 0 when nothing was detected), alongside the canonical `width`/`height`/`count`. It also carries `noise`, and on THIS event the field is in the plane's own units — the caller hands the detector an ADU-scaled copy (`measure::ADU_SCALE`), so the number is ~65535× the native `[0, 1]`-domain `noise` the sibling `"frame plane measured"` event reports; the event's `threshold` is in the same ADU units, which is the point of reading them together.

**Dictionary extension (stacking registration, `stacking::register`, 2026-09-09):** `detections` (usize; registration stars found on a frame, on the `"reference stars detected"` and `"frame registered"` debugs and the `"frame registration failed"` warn), `model` (string; the resolved registration model, e.g. `homography+polynomial3`, on `"frame registered"`), `flipped` (bool; the linear part has a negative determinant — reuses the registration domain's existing name on `"frame registered"`). Reuses `path`, `inliers`, `rms_px` (the solve domain's names, same meaning: refit inliers and the RMS through the final map), `error` and `duration_ms`. Reuses `note` (string; a non-fatal per-frame registration warning — an auto-distortion skip, a failed re-pairing pass, an RMS above the soft limit) on the `"registration warning"` warn, one event per warning, alongside `path`. `max` (f32; the plane's finite maximum on the `"plane exceeds native units; the saturation cut will drop every star"` warn — a calibrated plane is expected in [0, 1], a float32 source that kept ADU is the known offender).

**Dictionary extension (stacking integration, `stacking::integrate`, 2026-09-09):** `weight` (f64; a frame's lowest per-channel normalized weight, on the `"frame dropped below the minimum weight"` and `"reference frame is below the minimum weight but is never dropped"` warns, alongside `path`) and `min_weight` (f64; the configured floor it was compared against, same two warns — `IntegrationConfig::min_weight`). `weight_channels` (usize; a frame's own `weight.normalized` length, alongside the group's own `channels` (usize) it's compared against, on the `"weight channel count differs from the group; missing channels weigh zero"` warn, alongside `path`). `planes` (usize; new — the group's total plane count, on the `"group integration finished"` info, alongside the group-level sense of `frames` (included-frame count, both the `"group integration started"` and `"group integration finished"` infos) and `rejected_fraction` (f64; `rejected_low_fraction + rejected_high_fraction` — see `GroupStats`'s own doc for why that denominator, not `IntegrationOutput::rejected_fraction`'s)). Reuses `plane` (the measurement domain's per-plane index) on the `"plane integrated"` debug and the `"snr_gain is not finite…"` warn, `rejected_low`/`rejected_high` (u64; this plane's `StackOutput::rejected_low`/`rejected_high` counts) and `duration_ms` (this plane's own wall time) on that same debug, and `recipe` (the master-build domain's `IntegrationRecipe::describe()` string) on `"group integration started"`.

**Dictionary extension (WCS card writer, `fits_writer::wcs`, 2026-09-09):** `table` (string; which SIP table — A/B/AP/BP), `i`/`j` (usize; the term's powers of u and v) and `value` (f64) on the `"SIP low-order term written; CD fold not applied"` warn. `len` (usize; a buffer's element count) on `stacking::psf_signal`'s `"background residual: plane length does not match the geometry"` warn, alongside the already-canonical `width` / `height` — the guard is a public-API precondition (`background_residual` refuses a plane whose length is not `width × height`), not something only the `integrate_probe` example can trigger.

**Dictionary extension (stacking config, `stacking::config`, 2026-09-09):** `expected` (u32; the current `STACKING_CONFIG_VERSION`, alongside the decoded document's own `version`, on the `"stacking config version differs; decoding with the current defaults"` warn `resolve_config` emits when a stored/foreign config's `version` doesn't match — the document still decodes fine through `#[serde(default)]`, this just flags the drift instead of silently reusing an old/foreign shape's semantics).

**Dictionary extension (stacking run orchestration, `stacking::run`, Plan 5a Task 6, 2026-09-09):** `run_id` (i64; `stacking_runs.id` — the run-level identifier every run-thread event carries, from `"stacking run started"` through a per-frame `"calibration failed; frame excluded"` warn to `"stacking stage finished"`/`"stacking run finished"`) and `group_key` (string; an integration group's stable key, spec §2 — carried by group-scoped run events, including later stages' per-group progress/failure lines). `groups` (usize; the run's total integration-group count, on `"stacking run started"`) and `config_hash` (string; the resolved `StackingConfig`'s fingerprint, [`stacking::config::config_hash`] — the SAME hash `stacking_runs.config_hash` stores, on that same info, so a log line alone answers "was this the config I think it was"). Reuses `inliers`/`rms_px` (the registration domain's names, same meaning: refit inliers and the RMS through the final map) and `weight` (the integration domain's name: a frame's lowest per-channel normalized weight) for any run-thread event that reports a frame's registration or weight state — never a synonym. Reuses `count` (the top-level canonical field) for a group's included-frame tally on the `"stacking group skipped: fewer than 3 included frames"` warn — not `included`, see next. The `StackingProgressEvent`/`StackingCompleteEvent` payloads (`stacking-progress`/`stacking-complete`) are `ProgressEmitter` events, not `tracing` fields, per the fix-round-2 note below — their own `groupKey`/`frameId`/etc. carry no dictionary entry.

**Dictionary extension (stacking run orchestration, `stacking::run`, Plan 5a Task 7 fix round 1, 2026-09-09):** `reason` (string; why a frame was excluded from a stacking run — a stage-1 calibration failure, a stage-3 measurement failure or selection-filter miss, or a stage-5 registration failure — on every `"frame excluded"` warn, alongside `frame_id`) and `included` (bool; whether a frame enters the group's integration, i.e. `MeasuredFrame::included` at the moment it was logged — on the per-frame `"frame measured"` debug, alongside `weight`; a frame's own inclusion can still change later in the same stage, e.g. the manual-reference override, so this is a snapshot, not a final verdict).

**Dictionary extension (stacking run orchestration, `stacking::run`, Plan 5a Task 8, 2026-09-09):** `freed_bytes` (u64; bytes reclaimed by the Output stage's post-run cleanup pass — the sum of `stacking::paths::cleanup_work`'s own byte count over whichever subtrees `cfg.output.cleanup` removed — on the `"cleanup applied"` info, alongside `run_id`). **Dictionary extension (stacking plan gate + folders, `stacking::plan` + `api::stacking`, Plan 5a final fix wave item 4, 2026-09-09):** `frame_count` (usize; a frame set's total frame count across every integration group, on the `"stacking plan built"` debug) alongside `included_count` (usize; the subset still in scope after manual exclusions, same event); `blockers` (usize; the plan's own blocker count, same event) and `stale_stages` (usize; how many of the three cacheable per-frame stages — Calibrate, Measure, Register — a fresh run would still have to redo, same event). `working` / `output` (string; the two stacking folders' effective, already-validated paths — empty when a folder was just reset — on the `"stacking folders updated"` info `set_stacking_paths` emits after a save).

**Message style rule**: the message is a short, stable human phrase; all data lives in fields. `info!(root_id, new = 12, unchanged = 4219, "scan finished")` — never `info!("scan finished — 12 new of 4231")`. This is what makes events aggregatable and MCP-queryable.

**Per-domain required fields** (the catalog; enforced by the sweep tables and code review). "Required" means: present wherever the value exists at that point in the operation — an event before a value is computed omits it; the sweep tables specify exact fields per event:

| Domain | Required fields on every event |
| ---- | ---- |
| command boundary | span name = command name; duration = span-close `time.busy`/`time.idle` (FmtSpan::CLOSE built-ins — as-built, T4); failure = the `err`-emitted error event inside the span. The literal `duration_ms`/`outcome` names apply to hand-written events, not boundary spans. |
| scan | `root_id`, `path` (where per-file), counts (`seen`/`new`/`updated`/`errors` on summary) |
| solve | `frame_id`, `stage`, `scale_arcsec_px`, `inliers`, `rms_px`, `outcome`, confidence fields |
| registration | `frame_set_id`, `frame_id`, `flipped`, tolerance fields, group counts (gate) |
| calibration matching | `set_id`, `frame_set_id`, per-parameter mode, `score` |
| file op / archive | `operation_id`, `src`, `dest`, `strategy`/`stage`, hash-verify outcome |
| db maintenance | affected table, `count`, `duration_ms` |

**Spans**: every long-running operation opens a span named for the operation kind, carrying that kind's id field; all nested events inherit it. This is the correlation mechanism for "give me everything about operation X" (`log-mcp`'s `list_operations`/`get_operation`). As-built, six kinds: `scan` (`root_id`), `archive_op` (`operation_id`), `file_op` (`operation_id`), `solve` (`frame_id`), `export` (`frame_set_id`), `registration` (`frame_set_id`).

## Runtime level control

- Settings gains a **Logging** section: global level (`error|warn|info|debug`) + per-module overrides for `scanner`, `plate_solve`/solver, `calibration`, `archive`+`file_op`. Stored as one JSON value in the settings table (`logging.config`), mirrored by a TS type; applied live via the reload handle.
- Commands `get_logging_config` / `set_logging_config` in both backends.
- `ATHENAEUM_LOG` (full `EnvFilter` syntax, e.g. `info,athenaeum_core::scanner=trace`) overrides settings entirely while set; the UI shows an "overridden by environment" notice.
- Default when nothing configured: `info`.

## Command-boundary instrumentation

As-built (T4): each command/route function carries `#[tracing::instrument(skip_all, err)]` (Tauri) or `#[tracing::instrument(skip_all, err(Debug))]` (Axum, whose error type isn't `Display`) directly on the function — no separate wrapper/macro layer. The span is named for the function; its close event (`FmtSpan::CLOSE`, built into the subscriber stack) carries `time.busy`/`time.idle` as the duration record, superseding the literal `duration_ms`/`outcome` fields floated at design time. A failing command surfaces as the `err`-emitted `ERROR`-level event inside the span, not as an attribute on the close event — this is what structurally enforces never-swallow. Applied mechanically across all ~157 commands in both backends' command/route modules (323 annotated functions total: 160 Tauri + 163 web); a handful of high-frequency, low-value commands (`get_setting`/`set_setting`, per-frame preview/metrics fetches driven by UI index changes) are additionally marked `level = "debug"` so they don't spam the default `info` tier.

## The audit sweep

Every existing print site (~516 backend + submodule prints) is individually dispositioned in per-module tables (produced during planning, executed module-by-module): **level + domain + required fields**, or **delete** (dead progress prints superseded by `ProgressEmitter`). `ProgressEmitter` events remain events — "notify on outcomes, log everything" keeps the two systems separate.

## MCP log-query server (last phase; cut-able to a follow-up without redesign)

New workspace crate `crates/log-mcp`: a stdio MCP server over the JSONL directory (path via arg/env). Tools:

- `query_logs(level?, module?, contains?, since?, until?, limit?)`
- `tail_logs(n)`
- `list_operations(kind?, since?)` — from span-open/close events
- `get_operation(operation_id)` — every event under that operation across modules

Registered in the repo's `.mcp.json` for dev sessions. Reads the same files a beta user zips up — one code path to understand any log.

## Legacy cleanup (explicit)

The old logging style is removed entirely, not left beside the new one:

- `logging.rs`'s single-file writer and its `log(level, msg)` free-function API are deleted in the rewrite; no call sites may remain.
- First init of the new subscriber deletes the obsolete `<app-data>/athenaeum.log` and `athenaeum.log.1` files (crash.log stays — same mechanism, still written on panic).
- **Zero-print exit gate**: after the sweep, `println!`/`eprintln!` in production code of all five codebases = 0 (tests, benches, examples, and build scripts exempt; CLI binaries' intentional user-facing stdout in solvemyastro exempt and listed by file in the plan). Enforced as a checklist grep like Phase 0's naming gate.
- Frontend `console.*` sites stay (out of scope this cycle) — but the api layer's error paths touched by other work must not *add* new bare `console.log` for backend-reportable errors.

## Error handling

Logging never takes the app down: file-open failure → console-only + one `warn`; writer is non-blocking (full disk stalls the log thread, not operations); filter parse errors keep the previous filter and `warn`; subscriber init failure leaves the app running unlogged rather than dead.

## Performance

Disabled levels cost ~an atomic load per call site (tracing callsite caching); field evaluation and formatting are lazy. Hot-loop math logging sits at `trace` and is additionally coarse-grained (per-iteration summaries preferred over per-element where element counts are huge). Acceptance: `corpus_bench` regression gate unchanged at default (`info`) level.

## Testing

- Unit: settings-JSON → filter-directive parsing; canonical-dictionary helpers; rotation config.
- Integration: init produces parseable JSONL; live level flip via `set_logging_config` changes an emitted module's output; a real command invocation emits its boundary span with outcome; panic hook still writes `crash.log`.
- Submodules: suites green + `corpus_bench` gate (no measurable cost at `info`).
- MCP: tools against a fixture log directory.
