# starloom phase 0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. The `lean-execution` skill overrides it wherever the two conflict. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the stacking kernel, the integration engine, the calibration pixel math and the FITS/XISF writer core out of `athenaeum-core` into a new workspace crate `crates/starloom`. Athenaeum keeps every output byte, every old `athenaeum_core::` path, and every test.

**Architecture:**
- **Layout.** Starloom mirrors core's module paths (`starloom::stacking::integrate`, `starloom::integration::engine`, `starloom::fits_writer::card`, …), so nearly every `crate::` path inside a moved file stays verbatim. Public renaming is phase 1's job.
- **Old paths.** Core re-exports each moved module at its old path. Where a module keeps Athenaeum items, core holds a shim: a glob re-export of the starloom module, plus those items, plus wrappers with today's signatures that add the Athenaeum facts (gain, cards, creator, Settings).
- **Order.** Each layer is first copied into starloom and made green there. Only then is core switched to it and the core copy deleted.

**Tech Stack:** Rust (edition as in core), Cargo features, rayon, serde, ts-rs 12, tracing; rustafits and solvemyastro as path dependencies; the athenaeum-lab acceptance harness (zsh + Python).

**Review:** fable read this plan against the code on 2026-11-22; its nine findings are folded in (the shim rule, the test split rule, the gate rewrites, the flat-normalization seam, the base-layer storage class, the memory probe, the manifest, the early `test_support`, the ranges).

**Spec:** `docs/superpowers/specs/2026-11-22-starloom-extraction-design.md`. Read it before any task. Section numbers below (§…) and rulings (SL-…) refer to it. Line numbers are from `main` at 196f54a0. Paths are under `crates/athenaeum-core/src/` unless they start with `crates/`, `docs/`, `athenaeum-lab/` or a repo-root file.

## Deviations from the spec

Each is a plan-level call made to keep moved files and callers verbatim. None changes what the spec promises.

- **Module paths.** Starloom mirrors core's module paths (`starloom::stacking::…`, `starloom::integration::…`). The spec's `starloom::stack::{…}` was illustrative. The feature names `engine` and `stack` are as in the spec, and public names are polished in phase 1.
- **Settings resolvers.** The resolvers in `integration::band_budget` and `integration::io_policy` stay in core shim modules at their old paths, instead of moving to a new core module with edited callers (spec §4.4). This is the same rule (SL-5), with fewer edits.
- **Crop and median.** `crop` and `median_f64` live in starloom's `stacking` module (layer `stack`), not in the base layer: nothing outside stacking uses them.
- **Gain.** Starloom keeps `measure_frame*` with today's signatures, passing `gain: None`. It adds explicit-gain entry points, and core's shim restores the header read. This keeps every moved test verbatim (SL-6).

## Global Constraints

- **No output byte changes** (SL-6): masters, drizzle outputs, rejection and weight maps, `registration_results` rows, `.athln`, `.athf`, pass-1 artifacts, calibrated lights, calibration masters, every stage hash and `config_hash`, `src/types/*.ts`.
- **No pinned-hash test is edited.** The list is in spec §5.
- **No test is rewritten.** A test moves verbatim, or stays in core verbatim. The only allowed edits are `use` lines and paths. A test that asserts on an Athenaeum fact (an `ATH_*` card, `EGAIN × ATH_CSCL`, the Athenaeum `CREATOR`, Settings) stays in core.
- **Headless stays headless.** `cargo check -p athenaeum-core --no-default-features` passes, and `cargo tree -p athenaeum-core --no-default-features -e normal` lists neither `rustafits` nor `solvemyastro`.
- **Standalone manifest** (SL-12): `crates/starloom/Cargo.toml` has no `[workspace]` table and no `workspace = true` keys. Licence `Apache-2.0`.
- **Dependencies:** starloom never depends on `rusqlite`. If it depends on `serde_json`, it enables only `float_roundtrip`, never `preserve_order` or `arbitrary_precision`.
- **Starloom's own vocabulary:**
  - it writes and reads no `ATH_*` card of its own;
  - its environment variables are `STARLOOM_SCALAR_SELECTION` and `STARLOOM_REQUIRE_VECTOR_KERNEL`;
  - its default XISF creator is `starloom <starloom version>`, and Athenaeum's files keep `Athenaeum <athenaeum-core version>`.
- **Thread pools:** starloom never builds a rayon pool outside tests.
- **Naming:** never name another code base consulted (a solver, stacker or processing program) in code, comments, docs or commit messages; the comparison program is "the ERP". Never name the reference implementation of the debayer.
- **Tests:** every test passes on macOS, Linux and Windows; test names use letters, digits, `_` and `-` only.
- **Logging:** `tracing` only. No `println!` or `eprintln!` in production code. Message text and field names are unchanged by the move.
- **Disk rule:**
  - job data under `~/.athenaeum-acc/` with a row in `REGISTRY.tsv`, deleted once results are committed;
  - agents build into `CARGO_TARGET_DIR=target-agent`, and the lab into `.superpowers/target-acc`;
  - one implementer at a time (16 GB dev Mac).
- **Commits:** authored by the configured user (`eg013ra1n`) on branch `starloom-p0`; each message ends with the session's `Co-Authored-By:` and `Claude-Session:` trailers. Never push. `main` is merged only on the owner's word.

Starloom's manifest sets `[lints.rust] unexpected_cfgs = "deny"`, so a gate that names a feature starloom does not have fails the build instead of silently dropping tests.

**Shim rule.** A glob re-export is shadowed only by a local item of the same name in the same module. A moved `mod.rs` often re-exports a child's items one level up, for example `stacking/ln/mod.rs:76-80` re-exports `write_reference` and `write_reference_saturation` from `reference`. For every item a shim overrides, the parent shim also adds an explicit `pub use <child>::<item>;`; an explicit import beats the glob. Before a switch, grep each moved `mod.rs` for `pub use <child>::{…}` naming an overridden item, and record the list in the ledger.

**Test split rule.**
- A test stays in core when it asserts an Athenaeum fact, or when it sits in a split module (`weights.rs` 35 tests, `crop.rs` 10, `config.rs` 52, `wcs_seed.rs` 6) and touches a staying item. Otherwise it moves.
- A left-behind test takes a verbatim copy of each private test helper it uses. For example, the `to_record` tests use `stars` and `pair` (`register/frame.rs:545, 561`).
- A module-private item that a staying test reaches across the line becomes `pub` with `#[doc(hidden)]` in starloom.
- Each copy task records, per file, the `#[test]` count copied and the count `cargo test` ran. They must match.

Items that are `pub(crate)` today but are used across the new crate line become `pub`, with `#[doc(hidden)]` when not meant for users. Examples: `geometry::pixel_map::grid_counters`, `ln::fallback_counters`, `groups::median_f64`, `writer::rename_replace`, `xisf_writer::escape_xml`. Every `impl` block of a moved type moves with the type (the orphan rule); if such an impl needs an app item, stop and report.
