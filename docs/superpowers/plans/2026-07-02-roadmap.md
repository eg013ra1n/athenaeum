## Phase 2 — Master calibration library (medium)

- [ ] **rustafits linear decode API**: full-res `f32` planes, no stretch, BZERO/BSCALE applied, optional still-CFA output for OSC. Today the pipeline is render-only (`process_image` → stretched 8-bit), but `PixelData::Float32` already exists internally — this is an additive API, not a rework. Also the moment to decide FITS-writer placement (core vs rustafits; writer must NOT depend on the render pipeline either way).
- [ ] B2 integrator: streaming pixel combine (mean/median/sigma-clip); recipes bias/dark/flat/darkflat with the existing fallback chain for flat pre-calibration; on `operation_queue` + `ProgressEmitter` + cancellation.
- [ ] B3 header vocabulary (`IMAGETYP=MASTER *`, standard keys, `ATHM_*` namespace) + `master_provenance` table.
- [ ] Library folder = managed scan root; template-based master naming; scanner ingestion via existing is_master path (verify 1:1 master-set creation handles library masters cleanly).
- [ ] B4 UI: "Create Master" on calibration set; library browser (extend `MasterDarkLibrary.tsx` patterns).
- [ ] Matcher/export integration test: created master preferred per `MasterPreference`; WBPP/Siril export consumes library masters instead of raw calibration sets when linked.
- [ ] (Stretch, B5) in-app light calibration = stacking Phase A: apply masters to lights → calibrated f32 FITS. Feeds the stacking-engine roadmap directly.

## Phase 3 — Mosaic (medium; parallel with Phase 2)

- [ ] Schema: `frames_set.parent_set_id`, `set_kind`, `tile_label`.
- [ ] `mosaic/` module: OBJECT token parser (Panel/P/Tile/xNyM/NofM conventions) + WCS/FOV footprint adjacency detector; auto-suggest with user confirm; `mosaic.*` settings.
- [ ] Frame-set lifecycle audit for tiles: sessions, calibration links, archive, find-new-images all operate per-tile (tiles are ordinary frame sets — verify no code assumes flat set list, e.g. Objects page queries).
- [ ] Export: `{TILE}`/`{MOSAIC}` tokens; extend existing `WbppExportConfig`/`WbppSetupInstructions` (`export/models.rs:691`) with a post-processing `PANEL` keyword level (pre OFF / post ON).
- [ ] UI: mosaic parent view with tile list + coverage; SkyChart tile footprints (do the SkyChart decomposition from audit §2.5 first).
- [ ] E2E: real 2×2 mosaic dataset → detect → export → verify WBPP groups 4 panels sharing calibration.

## Phase 4 — Collaboration groundwork (medium)

- [ ] Stage 2 portable paths: `(scan_root_id, rel_path)` split with absolute-path transition column; update dual-pane move, archive restore, SUBSTR rename in the same pass.
- [ ] Stage 3 `change_log` (append-only, tombstoned deletes, capped).
- [ ] **Package export/import**: frame set (or tile) → files + `manifest.ndjson` (uuid-keyed, xxh3 hashes), optional zip via `zip_writer`; idempotent import with provenance (`origin_catalog_uuid`). Transport-free collaboration MVP — ships user value on its own.

## Phase 5 — P2P MVP: Syncthing (medium–large)

- [ ] `SharingTransport` trait; Syncthing implementation: sidecar detect/manage, REST-API config (device IDs, shared folder per project).
- [ ] `shared_projects` + `project_members` schema; `athenaeum-project.json`; project folder as special scan root; auto-import contributions on monitor events.
- [ ] Frontend: `SyncContext` + `useSyncStatus()`; project page (members, contributions, sync state); notifications via existing `notify()` kinds (+ `sync` kind).
- [ ] Two-machine E2E: create project → invite → both contribute → both catalogs converge.

## Phase 6 — Extensions (after MVP feedback)

- [ ] Group mosaic campaigns: tile plan in project manifest, tile claiming, per-member coverage, combined multi-contributor WBPP export.
- [ ] Torrent publishing via embeddable Rust session (librqbit): package → torrent + magnet, in-app seeding. One-shot dataset/master-pack distribution.
- [ ] Shared master library acceptance flow (imported masters require explicit accept).
- [ ] Scale work as catalogs grow: S1 clustering O(n²), S2 query pagination.
