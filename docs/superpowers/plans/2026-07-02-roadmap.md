## Phase 2 — Master calibration library (medium)

- [ ] **rustafits linear decode API**: full-res `f32` planes, no stretch, BZERO/BSCALE applied, optional still-CFA output for OSC. Today the pipeline is render-only (`process_image` → stretched 8-bit), but `PixelData::Float32` already exists internally — this is an additive API, not a rework. Also the moment to decide FITS-writer placement (core vs rustafits; writer must NOT depend on the render pipeline either way).
- [ ] **Calibration research spike** (before B2/B5 implementation): correct calibration paths, algorithms and mechanisms incl. the math — bias-based vs dark-based workflows (and dark+bias with dark optimization/scaling), flat normalization (master flat pre-corrected by darkflat/dark/bias), order of operations, output pedestal / negative clipping, OSC/CFA handling. Output: a short calibration spec that both the B2 integrator and B5 light calibrator follow.
- [ ] B2 integrator (**calibration stage 1 — master creation**): streaming pixel combine (mean/median/sigma-clip); recipes bias/dark/flat/darkflat with the existing fallback chain for flat pre-calibration; on `operation_queue` + `ProgressEmitter` + cancellation. Bias masters stay a first-class recipe so both dark-based and bias-based light-calibration paths are available (bias optional per the owner's model).
- [ ] B3 header vocabulary (`IMAGETYP=MASTER *`, standard keys, `ATH_*` namespace — renamed from `ATHM_*`, 8-char FITS keyword limit) + `master_provenance` table. Vocabulary module itself ships in Phase 1 (see `../specs/2026-07-04-phase1-foundation-design.md` §5); B3 populates it from calibration-set data.
- [ ] Library folder = managed scan root; template-based master naming; scanner ingestion via existing is_master path (verify 1:1 master-set creation handles library masters cleanly).
- [ ] B4 UI: "Create Master" on calibration set; library browser (extend `MasterDarkLibrary.tsx` patterns).
- [ ] Matcher/export integration test: created master preferred per `MasterPreference`; WBPP/Siril export consumes library masters instead of raw calibration sets when linked.
- [ ] B5 in-app light calibration (**calibration stage 2 — promoted from stretch to core deliverable, owner 2026-07-04**): apply master flats + darks/biases to lights → calibrated f32 FITS, exported so WBPP receives ready-to-register/normalize frames (calibration already done, WBPP calibration step skipped). = stacking Phase A; feeds the stacking-engine roadmap directly. Follows the calibration research spike above.

## Phase 5 — P2P MVP: Syncthing (medium–large)

- [ ] `SharingTransport` trait; Syncthing implementation: sidecar detect/manage, REST-API config (device IDs, shared folder per project).

- [ ] Shared master library acceptance flow (imported masters require explicit accept).
- [ ] Scale work as catalogs grow: S1 clustering O(n²), S2 query pagination.
