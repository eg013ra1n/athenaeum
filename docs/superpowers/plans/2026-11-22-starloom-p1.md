# starloom phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. The `lean-execution` skill overrides it wherever the two conflict. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Harden starloom's contract inside the workspace. No fact-less starloom entry point can appear under an `athenaeum_core::` path, a golden guard ties every stage's output to its version, each shared helper exists once, the features are clean and the public surface is documented. No output byte changes.

**Architecture:**
- **Shims by name.** The five core modules that shadow a starloom item to add an Athenaeum fact (gain, flat cards, `ATH_STK*` cards, creator) re-export starloom by an explicit list. A source-scan test keeps them that way.
- **Goldens.** One starloom integration test runs every stage on fixed synthetic inputs on a 2-thread pool. It keeps a table of (stage, platform, versions, xxh3 checksum); a float-free row's platform is `*`. Two signal versions, which enter no hash, give the two version-less stages a constant to bump. `MEASURE_STAGE_VERSION` versions starloom's own measure numbers and enters three hashes only past 1.
- **Surface.** One naming rule for the writers. Every `#[doc(hidden)]` item is decided. The crate root says `#![deny(missing_docs)]`.

**Tech Stack:** Rust, cargo features, rayon, serde / serde_json, xxhash-rust (xxh3), ts-rs 12, tracing; the athenaeum-lab acceptance harness (zsh + Python).

**Spec:** `docs/superpowers/specs/2026-11-22-starloom-extraction-design.md`: §8 "Phase 1", SL-7, §5, §4.4-§4.9 and §9. Also read phase 0's plan (`docs/superpowers/plans/2026-11-22-starloom-p0.md`) and the open-items section "Deferred to starloom phase 1" (`docs/superpowers/open-items.md:416-438`). Line numbers are from `main` at bd0e9ea2. Paths are repo-relative.

## Global Constraints

- **No output byte changes** (SL-6). This covers masters, drizzle outputs, rejection and weight maps, `registration_results` rows, `.athln`, `.athf`, pass-1 artifacts, calibrated lights, calibration masters, every stage hash and `config_hash`. `src/types/*.ts` may change only in `/** … */` blocks and whitespace (the token-stream compare, P1-R3), because ts-rs copies `///` docs into JSDoc (Plan note 7).
- **No pinned-hash test is edited** (the list is in spec §5).
- **Tests move or stay verbatim.** Three kinds of edit are allowed, and no assertion changes:
  - `use` lines and paths;
  - the one call in `starloom_xisf_creator_is_the_default` to a writer that Task 1 removes;
  - deleting the nine core tests in `zip_store/fs.rs` whose verbatim copies already run in starloom (Task 3).
- **Headless stays headless.** `cargo check -p athenaeum-core --no-default-features` passes, and `cargo tree -p athenaeum-core --no-default-features -e normal --prefix none | grep -E '^(rustafits|solvemyastro) '` prints nothing.
- **Standalone manifest** (SL-12): no `[workspace]` table, no `workspace = true` keys, Apache-2.0. `serde_json` enables only `float_roundtrip`; `rusqlite` is never a dependency. A path dev-dependency on starloom itself is allowed (publishing strips it).
- **Starloom's vocabulary.** It writes and reads no `ATH_*` card of its own, and after Task 5 no doc comment names one; the three `light_cal` debug messages keep theirs (SL-10, Plan note 8). Its environment variables are `STARLOOM_*`. Its default creator is `starloom <starloom version>`; Athenaeum's files keep `Athenaeum <athenaeum-core version>`.
- **No module renames.** Module paths are tracing targets the lab parses. Message text and field names do not change (SL-10). The one target change is Task 3's two `sync_best_effort` debug lines. Their text stays, and their new target joins the `archive` log category.
- **Thread pools:** starloom never builds a rayon pool outside tests (SL-9). The golden test builds its own 2-thread pool.
- **Naming:** never name another code base consulted (a solver, stacker or processing program) in code, comments, docs or commit messages; the comparison program is "the ERP". Never name the reference implementation of the debayer.
- **Tests:** every test passes on macOS, Linux and Windows; test names use letters, digits, `_` and `-` only.
- **Logging:** `tracing` only; no `println!` or `eprintln!` in production code. A test may `eprintln!`.
- **Disk rule:** job data lives under `~/.athenaeum-acc/` with a row in `REGISTRY.tsv`. The rulers are in the job folder `~/.athenaeum-acc/starloom-p0` (row until 2026-12-20). `~/.athenaeum-acc` is at about 381 of its 500 GB; Task 6 has the peak table.
- **Builds:** one implementer at a time (16 GB Mac); `CARGO_INCREMENTAL=0 CARGO_BUILD_JOBS=4`, `--test-threads=4`, `CARGO_TARGET_DIR=target-agent`. The lab builds into `<worktree>/.superpowers/target-acc`.
- **Commits:** authored by the configured user (`eg013ra1n`) on branch `starloom-p1` (`.claude/worktrees/starloom-p1`); each message ends with the session's `Co-Authored-By:` and `Claude-Session:` trailers. Implementers never push; the controller may push `wintest/starloom-p1` for the Windows run (phase 0 ruling R13). `main` is merged only on the owner's word.
- **Handoffs:** no `sleep`, `until` or `pgrep` wait loops. Use `run_in_background` and its notification. A server start is waited on with a single `curl --retry-connrefused` command.

2. **Generated TS after the doc pass.** `src/types/*.ts` changes in `/** … */` blocks and whitespace only, never a token of a type. Task 5 has the token-stream compare.
3. **Old paths still carry the fact.** `athenaeum_core::…` callers still get the gain, the flat cards, the scanner-skip cards and Athenaeum's creator, and no starloom fact-less entry point resolves under those paths. Test `fact_bearing_shims_reexport_by_name`, plus the guards named in Task 1 step 5.
4. **Writes to a network share** (archive, zip, export, header patch) still fall back to a plain `fsync` after the `sync_best_effort` dedup. The nine starloom sync tests and core's `archive`, `zip_store` and `fits_writer` tests pass, Task 3.
5. **Container memory limits** above, equal to or below physical memory give the same effective memory in core and in starloom. Test `binding_limit_keeps_only_a_limit_below_physical_memory`, plus `starloom_and_core_agree_on_effective_memory` (verbatim), Task 3.
6. **The measure-stage fold.** At 1 the key is absent, so every pinned hash keeps its bytes. Test `measure_stage_version_folds_only_past_1`, Task 2.

## Plan notes (the scope against the code)

1. **Five fact-bearing shims, not four.** `crates/athenaeum-core/src/stacking/ln/mod.rs:7` globs `starloom::stacking::ln::*`, and starloom's `ln` re-exports its own `write_reference(_saturation)`. Without an explicit list there too, a new fact-less writer would leak through the parent module. So the list covers `measure`, `light_cal`, `ln`, `ln::reference` and the `xisf_writer` module inside `fits_writer/mod.rs`. The other globs (`integration`, `crop`, `weights`, `register`, `register::frame`, `wcs_seed`, `band_budget`, `io_policy`) shadow nothing and stay.
2. **The open-items list of hidden items is incomplete.** Also hidden: `calibrate_light_compute_budgeted`, `parse_cgroup_limit`, `linux_total_ram_from`, `rename_replace`, `MAX_STR_CONTENT`, `Card::structural`, `escape_xml`, `ransac::degenerate` and the eight SL-17 hooks. Task 4 decides all 31 `#[doc(hidden)]` attributes.
3. **Memory helpers.** Only `parse_kb_field` and the effective-memory rule are shared. `sysctl_raw<T: Copy>` stays private in each crate: as a safe public function it would be unsound, since `T` can be any `Copy` type, a reference included. `read_trimmed` is `read_to_string(..).ok()` and stays private too.
4. **`solver` without `render` has always pulled rustafits.** `solvemyastro` depends on it (`solvemyastro/Cargo.toml:28`), so a CI line for that combination would fail whatever starloom did. The pick is the "accepted" sentence in the spec (Task 3); no CI line.
5. **The zero-stale check is a control comparison (P1-R5).** Phase 0's ruling R17 deleted `tierA-starloom-main/stackwork/LDN1272-test/registered`, so Register reads stale on any build. The ruler's own build on a second copy is the control, so no list is predicted. The Register hashes stay proven by the pinned tests of spec §5.
6. **Stages with no version of their own:**
   - The master-light combine (`integrate_group`) and the integration engine (`integrate_bias_like`, `integrate_flat`) get signal versions that enter no hash: `INTEGRATE_VERSION` and `ENGINE_VERSION`, both 1. Core's tripwire pins them, the `LIGHT_CAL_VERSION` pattern (SL-19). The cost is two constants and one new tripwire test. No cache keys these stages, so nothing is recomputed, and a bump fails Athenaeum's tripwire, so its acceptance is explicit.
   - Measure: resolved by P1-R1. `MEASURE_STAGE_VERSION` versions starloom's measure numbers, so a starloom-only change no longer needs a rustafits bump to reach the caches.
7. **ts-rs exports doc comments.** The rustdoc tasks change JSDoc blocks in `src/types/*.ts`, so phase 0's "no diff under `src/types/`" becomes "equal once `/** … */` blocks and whitespace are stripped" (P1-R3).
8. **The `ATH_*` names in the light-cal debug messages** (`crates/starloom/src/calibration_library/light_cal.rs:667`, `:734` with field `ath_fnrm`, `:741`). No live lab script parses them; only an archived results log contains the text. Proposal for the owner, not in this plan: neutral text ("from the flat's stamped per-channel constants", "from the flat's stamped constant", "(stamped constant absent)") and the field `stamped_norm`, as a log change accepted on purpose.
9. **`zip_store::fs` tests.** Core's nine sync tests are byte-identical to starloom's (`fs_util.rs` tests). Removing core's copy leaves each test running once, in starloom.
10. **Golden platforms.** This phase records float rows for `aarch64-macos` only: the dev Mac and the M4 Max lab runner. Rows for x86_64 Linux and Windows wait for public CI (P2-6). Until then those platforms check determinism and the `"*"` row only.

**What `check` does:**
- A `portable` stage is checked against its `"*"` row on every platform.
- When `platform` has no rows of its own, its float stages check determinism only. They pass, and the test `eprintln!`s "no golden rows for <platform>: determinism checked only" followed by every row literal.
- When the platform has rows, every computed stage needs one, and three messages are possible:
  - a recorded version that differs from `live`: `"<stage> (<platform>): <NAME> is <live>, the row was recorded at <v>: record the new row in the same change. New row: <literal>"`;
  - versions equal but the checksum differs: `"<stage> (<platform>): the output changed while <NAME> stayed <v>: bump <NAME> in the same change (SL-7) and record the new row; a change that moves no number records the row with the reason in its commit. New row: <literal>"`. `<NAME>` is the row's first version;
  - a stage with no row: `"<stage> (<platform>): no golden row; record: <literal>"`.
- All failures are reported in one `Err`, in table order. The first line names the upstream cause.
- Every message carries the row literal, so a CI log shows it. The `eprintln!` only serves recording, since a passing test hides it.
