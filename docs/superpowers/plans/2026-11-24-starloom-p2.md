# starloom phase 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. The `lean-execution` skill overrides it wherever the two conflict. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `starloom` command-line program calibrates, measures, registers, normalizes and stacks FITS/XISF frames from raw files without Athenaeum. Raw frames may be compressed (`.fz`, `.fits.gz`). On the same frames, masters and config, it writes the same bytes as Athenaeum's own run, stage by stage.

**Architecture:**
- **rustafits 1.10.0 first** (Tasks 1-4):
  - external PR #5 lands: `.fz`, `.fits.gz` and extension HDUs through fitsio-pure;
  - one public header reader, `astroimage::header`, by Athenaeum's catalog rules. It replaces `formats::stored_keys`, and every header read in rustafits goes through it (P2-R1);
  - a Moffat profile with the caller's β goes on the config wire (P2-R18).
- **Two new layers** in the starloom crate:
  - `pipeline` is a library: per-stage functions over plain files and a working folder, mirroring the pixel path of Athenaeum's `stacking::run` (P2-R3);
  - `cli` is a thin argument layer over it, plus a binary `starloom`;
  - neither is in `default`, and Athenaeum enables neither.
- **What `pipeline` needs from core moves into starloom verbatim**, and core re-exports it (P2-R5): the algorithm presets, the stage subtrees, the master recipe, the calibrated-light options, the debayer glue, the `.athf` format and the pure `run/` helpers. Athenaeum's bytes do not move.
- **Versioned public formats** connect the commands through the working folder: `measure.json`/`measure.csv`, `transforms.json`, `weights.json`, `.athf`, `.athln` and the manifest `starloom.json`, which also keeps the command history.

**Tech Stack:**
- Rust: the rustafits and starloom crates with their features, rayon, serde/serde_json.
- New dependencies:
  - `fitsio-pure` `=0.25.1` (from PR #5, Apache-2.0), new to Athenaeum's lock;
  - at the versions Athenaeum's lock already has: `clap` 4.6 (derive), `toml` 1, `glob` 0.3, `tracing-subscriber` 0.3 (`env-filter`, `json`).
- React/TS for the β field.
- The athenaeum-lab zsh/python harness.

## Review Focus

1. **An Athenaeum config given to `--config`.** It carries `grouping`, `reference`, `output`, `paths` and `version`. It parses, stderr names the ignored keys, and `config show` prints the seven algorithm subtrees with Athenaeum's values. Test in Task 15.
2. **A changed chain.**
   - The user re-runs `calibrate` with another dark, then runs `stack` on the old `measure.json`. It refuses, naming the stage to re-run (Tasks 8 and 15).
   - The user passes `stack --weights psfSnr` after a `measure` in another mode. It re-weighs from the stored measurements without re-measuring, and says so (Tasks 13 and 15). When the new weights change the LN members, it asks for `starloom normalize` instead of stacking on a stale `.athln`.
3. **A mismatch found late.**
   - A dark of another size, or a 3-plane light, is refused before any pixel is read, naming the file; it must not fail an hour into calibration. The sizes of a `.fz` frame come from its logical header.

   Tests in Task 9.
4. **The same stem in two places**, e.g. two nights' `Light_0001.fit`, or `Light_0001.fit` next to `Light_0001.fits.gz`. It is refused at input time, not silently overwritten in `calibrated/` and `fits/`. Test in Task 8.
5. **Windows paths.** This covers folders with spaces, mixed-case extensions, globs the shell did not expand, and drive letters in the manifest. Paths are stored after `std::path::absolute` and compared as `Path`s. Test in Task 8, run on Windows CI (Task 17).
