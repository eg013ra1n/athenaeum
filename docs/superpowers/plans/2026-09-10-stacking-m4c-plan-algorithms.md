# Stacking M4c — Rejection and Registration Algorithms Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The algorithm items of spec §14 M4 that live inside the integration engine and the registration stage: three more pixel-rejection algorithms (generalized ESD, RCR, min/max), the Winsorized sigma clipping aligned with the reference semantics (spec §6.3's deferred re-pin), large-scale pixel rejection (satellite trails and other structures the per-pixel algorithms leave as speckle), thin-plate-spline distortion with the local distortion loop, and the two local-normalization leftovers (the per-cell local scale spline behind the disabled `localScale` toggle, the barycentre second matching pass).

**Architecture:** Every addition is a new arm on an existing enum or a new optional stage inside an existing one; no table changes, no new commands. `Rejection` (engine) and `RejectionChoice` (config) grow `MinMax`/`Esd`/`Rcr`; the Winsorized algorithm changes in place (a fingerprint re-pin, measured before/after on real masters). Large-scale rejection reuses M3's per-frame `.rej` bitmaps as the per-frame rejection maps: after the first integration pass the bitmaps are post-processed per frame (large structures kept, speckle erased, then grown) and a second pass re-integrates with the processed bitmaps as FORCED rejections through a `RejectionBitSource` symmetric to M3's sink. TPS distortion is a new `geometry/tps.rs` fitted on the RANSAC inliers with a node cap and smoothing, evaluated through an 8-px displacement grid cached in memory (the spline itself is what `transform_json` stores), plugged into `PixelMap` as a second distortion kind beside the polynomial; the local distortion loop wraps the existing pair→RANSAC→refit steps. LN's local scale reuses the same TPS on the matched-star flux-ratio residuals.

**Tech Stack:** Rust (athenaeum-core `integration/{combine,engine,source}.rs`, `stacking/{integrate,run,rej,robust}.rs`, `stacking/register/align.rs`, `geometry/{tps,pixel_map,polynomial}.rs`, `stacking/ln/{scale,grid,mod}.rs`), React/TS (`IntegratePanel.tsx`, `RegisterPanel.tsx`, `NormalizePanel.tsx`, `stageSummary.ts`), ts-rs regeneration, no new dependencies (linear algebra hand-rolled as `geometry/eigen.rs` already is: a dense Cholesky solve for the TPS system).

**Spec:** `docs/superpowers/specs/2026-09-08-stacking-pipeline-design.md` §3.3 (models), §5.2 (LN), §6.2–6.3 (rejection maps, the menu, the Winsorized deferral), §9.2, §14 M4 · **Math:** `docs/superpowers/research/2026-09-08-stacking-math-reference.md` §3.4 (min/max, Winsorized, ESD, RCR — formulas verbatim), §3.5 (large-scale rejection), §4.3 (LN scale: barycentre pass, local scale spline), §5.3 (TPS, local distortion loop) · **Prior rulings:** M4a R-M4a-4 (the robust linear-fit line + `LINEAR_FIT_SIGMA_SCALE`), M3 R-M3-8 (`.rej` bitmaps are per-run temporaries — Task 3 extends their producer condition), M4b R-M4b-5 (per-group geometry — Task 3 reads `geometry_of`).

## Rulings made while planning (binding unless the spec says otherwise)

- **R-M4c-1 ESD/RCR/min-max are user choices, never Auto.** `RejectionChoice::resolve`'s Auto ladder is unchanged (percentile < 8, Winsorized < 20, linear fit ≥ 20). Defaults when chosen: `MinMax { low: 1, high: 1 }`; `Esd { outliersFraction: 0.3, alpha: 0.05, lowRelaxation: 1.5 }`; `Rcr { limit: 0.5 }`.
- **R-M4c-2 Student's t quantile without a dependency.** `t_quantile(p, nu)` = bisection on the regularized incomplete beta `I_x(a, b)` evaluated by Lentz's continued fraction (Numerical Recipes 6.4), `a = nu/2`, `b = 1/2`; the ESD critical value `λ_i` is computed per `i` from it. The (n, i) → λ table is memoised per stack size in a thread-local `Vec` (stack sizes repeat 26 M times per plane), so the incomplete beta is evaluated at most `k` times per distinct `n`.
- **R-M4c-3 Winsorized: the reference's loop with a cheap initial scale.** `μ = median`, initial `σ = 1.4826·MAD` (NOT `1.1926·Sn` — `Sn` is O(n²) per pixel stack; the loop converges to the same fixed point from either start on every real stack we can test, and the first-pass cutoff `5σ` makes the start point nearly irrelevant; documented deviation), then exactly math §3.4's loop: `t0 = μ − 1.5σ`, `t1 = μ + 1.5σ`; first pass cutoff 5 (a value beyond `μ ± 5σ` becomes `μ`, else clamped to `[t0, t1]`), later passes plain clamping; `σ = 1.134·stddev(v)`, `μ = mean(v)`; stop when `|Δσ|/σ < 0.0005` after ≥ 2 passes, cap 20 passes; then sigma clipping about `(μ_w, σ_w)` iterated until stable. The fingerprint pins that use Winsorized move; the commit records old/new fingerprints and the before/after master statistics (Task 2 Step 3).
- **R-M4c-4 Large-scale rejection reuses the `.rej` bitmaps and a second pass.** `integration.largeScale { low: bool, high: bool, protectedLayers: 2, growth: 2 }` (defaults off/off). When either side is on, stage 7 produces the `.rej` bitmaps even without drizzle (the M3 sink's condition becomes `drizzle.enabled && drizzle.useRejection || largeScale.low || largeScale.high`); per frame per plane the bitmap is post-processed — the rejected set is filtered to structures that survive a median filter of window `2^(protectedLayers+1) + 1` (binary median: a rejected pixel survives when more than half of its window is rejected — OUR formulation of "MMT keeping only the residual erases blobs smaller than ~2^layers px", stated as such in the doc comment), then dilated with a disc of diameter `2·growth + 1` — and written back as a `.rejl` sibling; the second pass (`integrate_planes` with `StackParams.forced_rejection: Option<&dyn RejectionBitSource>`) treats a set bit as "rejected before any algorithm runs" and combines the survivors as usual. Low and high sides are processed separately only when the bitmap format carries the side — it does not (M3's format is one bit per pixel: rejected or not); ruling: the M4c bitmap stays one bit and `low`/`high` both mean "process the rejected set" — the two flags are ORed into one `enabled` with a doc comment saying the side split is not carried (the reference's uint8 map does carry it; ours would cost a format bump for a distinction no acceptance test can see). Cost: one more integration pass when enabled; the `.rej` bitmaps are still removed at the run's exit unless `keepAll`.
- **R-M4c-5 TPS shape, cap and grid.** `geometry/tps.rs::ThinPlateSpline { nodes: Vec<(f64, f64)>, wx: Vec<f64>, wy: Vec<f64>, ax: [f64; 3], ay: [f64; 3], smoothing: f64 }` — the classic order-2 RBF `φ(r) = r² ln r` with an affine part, two independent scalar splines (x and y displacements) sharing nodes, solved by a dense Cholesky of `(K + λI)` bordered by the affine block (Bookstein's system). Node cap `TPS_MAX_NODES = 600`: when the inlier count exceeds it, nodes are picked grid-stratified over the reference frame (a 30×20 cell grid, the best-σ pair per cell first, then round-robin) — never the first N. Smoothing `registration.tpsSmoothing` (f64, default `0.0` = interpolating; the reference's default is its own — spec §15 says ours come from the acceptance run: Task 7 tries {0, 0.5, 2} px² and records the choice). Forward and inverse splines are fitted independently (inverse on swapped pairs, the same node positions in reference space). Evaluation for pixel work goes through `TpsGrid` — displacements sampled every `TPS_GRID_PX = 8` px over the frame plus one margin cell, bilinear between samples — built once per `PixelMap` on first use (`OnceCell`) and never serialized; `transform_json` stores the spline (≤ 600 × 4 f64 ≈ 20 KB).
- **R-M4c-6 Distortion is an enum now.** `PixelMap.distortion: Option<Distortion>` becomes `Option<DistortionModel>` with `#[serde(untagged)]`-free explicit tagging: `{ "kind": "polynomial", … }` | `{ "kind": "tps", … }`; a stored `transform_json` with no `kind` (every M1–M4b row) decodes as polynomial (`#[serde(default = "polynomial")]` on the tag through a custom `Deserialize`). `DistortionChoice` gains `Tps`; `Auto` never picks TPS (it stays polynomial by inlier count — TPS is a user choice, ruling like R-M4c-1). `model_name` yields `homography+tps`.
- **R-M4c-7 Local distortion loop.** With `registration.localDistortion: bool` (default false) and any distortion model on: after the first map, up to `LOCAL_DISTORTION_ROUNDS = 3` rounds of { re-pair every subject star through the current map with tolerance `ransacTolerancePx · (1 + round)`; RANSAC a corrector homography `H_c` on the residual pairs (reference-predicted vs reference-actual); stop when `‖H_c − I‖_F < LOCAL_DISTORTION_STOP = 1e-3`; otherwise compose `H_c` into the linear part and refit the distortion }. Each round logs `inliers`/`rms_px`; the final `Alignment.refit_rounds` counts them.
- **R-M4c-8 LN local scale.** `normalization.local.localScale = true` fits an approximating TPS (smoothing `5·σ_z`, node cap 600, the matched stars' positions in reference coordinates) on the residuals `z_k − scale` and samples `A(x, y) = scale + tps(x, y)` on the stride grid; `A` stays the constant `scale` when fewer than `LN_LOCAL_SCALE_MIN_STARS = 40` matches survive RCR (warn once per frame). The sidecar format is unchanged (it already stores a full `A` grid). The `.athln` config hash folds `localScale` in (it already hashes the whole `local` block — verify).
- **R-M4c-9 Barycentre second pass.** In `ln::scale::relative_scale`, when fewer than 80 % of the reference fits matched, a second pass matches the DETECTION barycentres (the seeds' `x, y` before the PSF fit) with the same 4-px half-side, and the larger of the two pairings is used; `ln_matches` on the debug line reports the chosen set and a new `ln_pass` field (1 | 2) says which.
- **R-M4c-10 Acceptance data.** LDN 1272 (both groups) for rejection/TPS/LN items; for large-scale rejection the run must contain a real satellite trail — the M2/M3 rejection-high maps are inspected first (`rejection_high` FITS of run 12's `keepAll` outputs, if still present, else a fresh run with `writeRejectionMaps`); if no trail exists in the set, Task 7 injects one (a synthetic 3-px-wide diagonal line at 5× background added to ONE calibrated frame's copy, swapped in via a scratch copy of the calibrated artifact — documented in the note as synthetic).
