# starloom phase 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. The `lean-execution` skill overrides it wherever the two conflict. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Starloom becomes its own public GitHub repository, buildable and testable alone, and Athenaeum consumes it as a submodule at `starloom/`, with one copy of rustafits and solvemyastro in the workspace and no output byte changed.

**Architecture:**
- **Dependencies by version (SL-18).** Starloom names `rustafits = "1.9.1"` (crates.io) and solvemyastro by git revision; solvemyastro names rustafits by version too. Athenaeum `[patch]`es both back to its submodule paths, so the workspace still builds one copy of each, from the submodules.
- **One squashed commit (SL-16).** The repository starts from `crates/starloom` at the merged head of Tasks 1-3 plus the files only a repository needs (lock, toolchain, CI, release workflow, changelog). Comments that point into Athenaeum's tree are fixed before the squash.
- **The switch.** `crates/starloom` is removed and the submodule `starloom/` added at the tag `v0.1.0`; every manifest, Dockerfile, CI and doc path follows.

**Tech Stack:** Cargo (`[patch]`, git and registry sources, `--locked`), git submodules, GitHub Actions, `gh`, gitleaks.

**Spec:** `docs/superpowers/specs/2026-11-22-starloom-extraction-design.md`: §8 "Phase 3", SL-12, SL-14, SL-16, SL-18, §5 and §9. Also the phase-1 plan (`docs/superpowers/plans/2026-11-22-starloom-p1.md`) and open-items "Starloom: left after phase 1" (`docs/superpowers/open-items.md`). Line numbers are from `main` at baedea30. Paths are repo-relative. Phase 2 (the CLI) is not a prerequisite: spec §7 and Q3 say nothing in phases 0-3 depends on it, and its work then lands in starloom's own repository.
