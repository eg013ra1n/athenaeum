## What's New

- **Archive feature** — finished frame sets can be packaged into one `.zip` per frame type (Lights / Flats / Darks / Bias / DarkFlats) inside a user-configured archive folder, while preserving all catalog metadata. The frame set then lives on a dedicated **Archive** page; you can browse it, see what's inside the zips, restore it, or delete it permanently. Three-state lifecycle on FrameSetDetail: stage/WIP shows **Find new images** + **Move to Archive**; in-archive-not-yet-zipped shows **Move and ZIP**; zipped shows **Unarchive** plus a folder-icon to reveal the zip(s) in the system file manager
- **Multi-folder archive destinations** — configure as many archive folders as you like in **File Manager → Monitored Directories → Archive Folders**, mark one as the default, and pick a destination per archive when more than one is configured. Each folder row is expandable to show which frame sets are archived inside it and their individual zip files (with size, missing-file warnings, and per-zip reveal-in-file-manager)
- **Calibration disposition per archive** — the Move-and-ZIP dialog asks Move / Copy / Skip per calibration type. Move is auto-disabled with a tooltip when a calibration is shared with other (non-archived) frame sets so you don't break their calibration chain
- **Reconcile-based restore** — extracting an archive checks per-file what's already on disk and only restores the missing pieces. Copy-disposition calibrations whose originals were never deleted are skipped (no duplicates), and the cross-archive case (calibration copied by one archive then moved by another) heals correctly regardless of restore order. Pre-flight check fires if any zip referenced by the plan is missing on disk
- **Smooth per-file archive progress** — every stage (Copying / Verifying / Building zip / Verifying zip / Deleting sources / Finalizing) emits per-file progress, including inside `build_zip` via a per-entry callback, so the bar advances smoothly through long runs instead of jumping per-zip. Restore reuses the same widget with the same progress channel
- **Operation safety** — DB-backed step log, hash verification at every stage, cancel triggers automatic rollback that restores moved sources from the staging area, and a top-of-app resume banner appears at startup if a previous archive operation was interrupted (Resume / Roll back / Decide later)

## Changes

- **FrameSetDetail toolbar** uses a single contextual button driven by the frame set's lifecycle state instead of stacking unrelated actions. The Locate column in the lights table is hidden when the frame set is zipped (paths no longer point to anything)
- **Objects page archive cards/rows** no longer show a quick-Unarchive shortcut. The Unarchive action is centralized on the FrameSetDetail toolbar so the dialog with destination picker, overwrite, and keep-zip toggles is the single source of truth
- **Settings → Archive** keeps only the global Compression preference (Store / Deflate). Folder management moved to File Manager → Monitored Directories → Archive Folders
- **`frames_set.is_archived`** is now a hard gate for ZIP archiving — a frame set must already be in the Archive section (move it there from stage/WIP first) before the planner allows zipping. The Move-and-ZIP button only appears once the set is in the Archive tab
- **Web mirror** — every archive Tauri command has a matching Axum route under `/api/...` so the web build has full archive parity, with progress events broadcast over the existing SSE channel

## Bug Fixes

- Fixed an off-by-one in the `get_files` row mapping introduced when adding archive columns to the `files` table. The `Frame` half of each `(File, Option<Frame>)` returned by the Files page was reading every field one column past where the SQL placed it; metadata like `object`, `date_obs`, `telescop` would have come back wrong. Caught by the spec-compliance reviewer and fixed before any user-visible regression shipped
- Restore now always cleans up its temporary extraction directory on any error path (previously it only cleaned up on cancel and hash-mismatch — file-open errors during extract would leak the temp dir until the next restore attempt)
- The `ArchiveProgress` widget no longer says "Failed — rolled back" for restore failures (restore doesn't roll back partial extracts the way archive's rollback restores moved sources). Restore-kind finishes now show "Failed" or "Cancelled" without the misleading suffix
