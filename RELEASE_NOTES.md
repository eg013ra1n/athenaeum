_The library-scale release: folders become a workspace, the observatory agent grows a file browser, color calibration goes per-channel — and Athenaeum goes open source._

## What's New

- **Athenaeum is open source.** The full source code now lives at [github.com/eg013ra1n/athenaeum](https://github.com/eg013ra1n/athenaeum) under the Apache-2.0 license — the desktop app, the web build, the plate solver and the image-rendering library included. Bug reports, feature discussions and pull requests are welcome; `CONTRIBUTING.md` explains how to build from source on every platform.
- **Folders is a workspace now.** The Monitored Directories list grew into a full master-detail screen: every folder shows its role (library, calibration library, archive), live statistics, health badges and an inline rescan; an offline volume gets a banner instead of silent absence; adding a folder walks you through a dry-run validation that says what would happen before anything does. Switching the calibration library to another folder is one step, with the consequences spelled out.
- **A file browser for the observatory agent.** Perseus' web page gains a Library tab that shows exactly what the agent watches: every capture folder, one directory at a time, with a status on each file — never sent, waiting for the next send, in flight, delivered, or declined — and how many batches it took part in. Select any frame and preview it right there, then walk the whole folder with the arrow keys: a pre-blink pass over the night without copying anything down first.
- **Send anything, again, anywhere.** Pick any files or folders in Perseus' Library and send them now, to all your devices or to one you choose — including files that were already sent, which is the point. Any past transfer can be re-sent to a different device from its history row: it goes out as a brand-new transfer, rebuilt from the originals still on disk, and honestly says "sends 97 of 100" when three of them are gone. Whatever the receiving device already has is skipped automatically.
- **Sends on a schedule.** Alongside "as soon as files settle" and "only when I press send", Perseus can now flush everything pending at fixed times of day: set 06:00, or 06:00 and 14:30, and the whole night goes out in one batch at that moment. The agent's page shows the next scheduled send, and if the machine was asleep across a scheduled time it catches up once — once, not once per missed slot.
- **One mirror tree on the receiving side.** Files arriving from a Perseus agent now land in a single stable folder tree per observatory — the same layout as the capture machine — instead of a new folder per batch. Each night's files simply appear in place; nothing previously received ever re-materializes or gets overwritten. Per-batch folders remain available as a checkbox for a one-off send.
- **Delete on the agent, and know what happens.** Deletion in Perseus' Library is never blocked. Before it happens the agent tells you the consequence: a file still waiting to be sent leaves the queue, a file inside an uploading transfer does not disturb it, a file from a delivered batch shrinks what "send again" can rebuild. Every manual deletion lands in the same audit log as automatic cleanup, each capture folder carries a free-space chip that turns red when the disk runs low, and the retention card states in plain words exactly what the agent will delete and when — per file.
- **Color calibration, per channel.** Master flats built from color (OSC) frames now carry per-Bayer-channel normalization, and calibrating color lights scales each channel by its own constant — flat correction no longer tints one channel to balance another. The CFA pattern is read wherever the file declares it, XISF's ColorFilterArray element included, and a mismatch between a light and its masters is called out in the readiness dialog before you run.
- **Masters can be deleted honestly.** Deleting a built master calibration file now restores its raw calibration set to service — every light that pointed at the master points back at the raw frames, and the library shows the lineage again. Nothing is left dangling.

## Changes

- **Removing a folder from the catalog is near-instant.** On a large library it took the better part of an hour; it now completes in seconds, and the Duplicates screen opens promptly on very large catalogs, loading groups a page at a time.
- **Scanning is substantially faster.** Content hashing left the scan path: new files are cataloged at full speed, and the hash index that transfer dedup uses is built by a visible, cancellable background job that runs only when sync is set up — with a status card in Settings.
- **Previously calibrated lights show "stale" after this update.** The light-calibration engine changed (per-channel flats), so every earlier output is honestly marked for re-calibration rather than silently kept.
- Transfers between devices now preserve OSC Bayer metadata end-to-end, and frames received by earlier versions with erased CFA cards are repaired automatically on the next scan.
- One duplicate notification is possible immediately after the upgrade — dedupe keys now include the notification kind.
- JPEG previews are encoded in pure Rust on every platform; building from source no longer needs a C toolchain for image work. Dependencies across the workspace are at current stable versions.

## Bug Fixes

- **Windows catalogs survive folder operations again.** Relinking a moved folder no longer sweeps files from sibling folders that share a name prefix; restoring an archive to its original location works on Windows paths; folder views tolerate trailing separators; and recreating calibration sets after a relink no longer mixes frames from sibling roots.
- **Ghost masters are gone.** A master whose file was removed from disk no longer lingers in the library or gets auto-linked to new lights; a one-time sweep clears the ones already accumulated.
- **Large-catalog stability.** "Database is locked" failures under concurrent work and "too many SQL variables" errors on very large operations are fixed; transactions across the catalog follow one discipline.
- **The web build catches up.** Archive progress in the browser reaches completion instead of stalling at the end; sky-map rectangle selection works again; web routes mirror the desktop's behavior for the new folder and calibration commands.
- Sending a frame to the Void is catalog-first: if the file itself cannot be removed, the catalog entry still goes, and a later rescan re-ingests the orphan instead of erroring forever. Permanently unparseable files no longer produce a recurring scan error on every pass.
- A one-time silent sweep on first launch removes consumer-link rows leaked by earlier deletions.
